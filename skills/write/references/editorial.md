# Editorial acceptance criteria

| Artifact | What the reader needs |
|---|---|
| Decision brief | Decision, viable options, evidence, tradeoffs, recommendation and uncertainty |
| Proposal | Problem, deliverables, exclusions, dependencies, supplied commercial terms and next action |
| Report | Main finding, method and coverage, supporting evidence, limits and implications |
| How-to | Prerequisites, ordered actions, expected result, recovery for likely failures |
| Knowledge note | Clear subject, source context, reusable conclusions and links to related existing notes |

Use these as questions, not mandatory headings. Preserve the project's chosen
format. Meeting notes distinguish decisions, proposals and open questions;
name an owner or deadline only if the source supplies one.

Perform a claim pass before the prose pass: verify names, quantities, dates,
URLs and attribution; distinguish estimates from observed results. If a draft
says “guaranteed” and the source says “expected”, restore the qualification.
Quoted words must match the source and fit permitted quotation limits.

Then read for purpose: can the reader find the answer and take the intended
next step? Remove throat-clearing, repeated conclusions, unearned adjectives
and facts that do not help. Keep technical detail where it explains a decision.

For revisions, compare both directions: what was lost from the original, and
what new claim or obligation appeared? For exports, inspect tables, footnotes,
page breaks, text overflow and links using the actual final file. If export or
rendering is unavailable, distinguish an edited source from a verified export.
