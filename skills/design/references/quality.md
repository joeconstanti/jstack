# Visual acceptance criteria

Use only criteria relevant to the target. A short brief should name the reader,
task, chosen direction, constraints and how acceptance will be observed.

| Medium | Questions to answer in the actual artifact |
|---|---|
| Interface | Is the primary action obvious? Do hierarchy and density support the task? Can keyboard users reach controls and see focus? Are errors recoverable? Does long content work on mobile? |
| Presentation | Does each slide make a clear point? Can the intended audience read labels at presentation size? Do sequence and diagrams support the argument? |
| Document | Can readers scan headings, distinguish evidence from recommendations and read tables? Do pagination, captions and links survive export? |

For all media, inspect type scale and line length, alignment and spacing rhythm,
contrast, image relevance and crop, content completeness and consistency. Test
contrast with a tool when claiming a ratio; a screenshot alone cannot prove it.
Do not infer accessibility conformance from an automated checker alone.

A design finding should connect a visible fact to a user consequence. Example:
“On slide 4 the legend wraps across the chart; readers cannot map colours to
series. Move it below and inspect the exported slide.” “Looks generic” is not
an actionable finding. Aesthetic preferences need a link to the brief.

References guide decisions rather than supply a mandatory look. Do not impose
font bans, one-screen sections, animation quotas or a starter framework. Record
asset provenance and licensing; generated imagery is not product evidence.

Finish an improvement loop when the requested acceptance criteria pass and no
high-impact finding remains in scope. If the necessary renderer is unavailable,
deliver the source with that gap, not a visual pass.
