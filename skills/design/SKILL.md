# design

Read `.agents/jstack/rules.md` first and apply it.

1. **Frame the job.** Read existing product and design guidance and inspect the
   actual artifact. Identify audience, primary task, medium and constraints.
   For existing work, name what already works before proposing changes.
2. **Choose the mode.** A critique returns findings; a brief returns a direction;
   implement only when requested. Read `references/quality.md` beside this file
   for the relevant medium. Use an installed specialist when its task fits.
3. **Make direction concrete.** Ground type, hierarchy, grid, spacing, colour,
   imagery and motion in the audience and supplied references. Explain which
   reference property helps the task; do not clone its branding. Use existing
   tokens first. Offer alternatives only for a consequential unresolved choice,
   then recommend one.
4. **Test the weakest part.** In implementation mode, work on a representative
   page, slide or component first, using realistic copy and assets. Include a
   constrained state: narrow width, long title, missing image or error. Inspect
   the rendered result before extending the direction across the artifact.
5. **Assess and refine.** Compare against the brief using the reference criteria.
   Rank problems by reader/task impact with an exact location, evidence and
   proposed correction. For critique, select the smallest set of findings that
   changes the next design decision; combine related observations. In
   implementation mode, correct the highest-impact issue and inspect again.
   Label source-only visual judgments unverified once, not in each finding.
6. **Deliver** the direction or changed artifact, rationale, checks and remaining
   tradeoffs. Record reusable decisions in the project's existing design docs
   when requested or needed for the implementation; do not create a competing
   design system. Use the verify skill for final rendered acceptance.
